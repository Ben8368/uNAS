# 文件、网址 App 与共享外观验收

日期：2026-09-08。范围：Phase 2 前端与 File Workspace 已实现边界，不接入真实处理引擎、云端或远程代码。

## 改动与覆盖

- Files 增加目录搜索、排序、面包屑路径导航和受限直接子项编辑，并覆盖取消授权、忘记目录与长名称布局。
- Browser Link App 收敛新增、编辑、删除和打开流程；Link App 仍只允许声明式 HTTPS 跳转。
- Desktop、Downloader、Settings、右侧状态面板与窗口表面统一中性层级，并覆盖深浅主题和窄窗口布局。
- 自动化目录用例使用隔离 OPFS handle 替身，不代表原生 OS picker、真实目录撤销、配额压力或导出能力。

截图场景包含目录 1440px 深浅主题、390px 窄窗口、可写状态布局，以及网址 App 的长名称与窗口层级。自动化只断言可重复行为和关键布局约束，不替代维护者对视觉偏好、真实触控、系统 Chrome 与浏览器缩放的人工确认。

## CI 失败与修复

GitHub Actions run 34200377549 的 `Docs governance` 与 `Verify demo` 同时失败，直接原因是 `CONTEXT.md` 把被 Git 忽略的 `apps/extension/test-results/extension-e2e/` 写成 Markdown 链接：本机残留目录让检查通过，干净检出的 Ubuntu runner 中目录不存在。`Browser regression` 因依赖 `Verify demo` 而被跳过，并非 E2E 自身失败。

修复后，`CONTEXT.md` 和风险台账改为链接本文件；生成产物路径只作为位置说明。治理检查同时增加 Git ignore 判定，确保本地存在的忽略目录也不能再伪装成有效的持久证据链接。
