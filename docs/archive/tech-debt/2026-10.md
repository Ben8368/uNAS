# 2026-10 技术债归档

## TD-004：AdBlock 顶层页面发送方策略宽于注释声明

**关闭日期：** 2026-10-10

**优先级 / 位置 / 来源：** P2；`apps/extension/src/platform/extension/sender-policy.ts` 的 `isAdBlockSender`；2026-10-09 router 拆分时由测试发现。

**问题描述：** 注释写"web pages may only request cosmetic rules"，实际只有子 frame 被限定为精确的 `getCosmeticRules`；顶层 HTTP(S) 页面的内容脚本发送方可发送任意 AdBlock 消息类型（含 `pauseBlockingForSite`、`refreshBlockingSubscriptions`）。这虽然需要本扩展注入的内容脚本（`sender.id` 校验），但被攻陷的内容脚本可暂停某站点拦截。

**关闭方案：** 2026-10-10 收紧为所有网页来源（顶层和子 frame）只接受精确 `getCosmeticRules` 请求；其他 AdBlock 消息要求授权扩展页面（`/newtab.html`、`/workspace.html`）。

**相关修改：**
- `apps/extension/src/platform/extension/sender-policy.ts`：更新 `isAdBlockSender` 注释和实现，所有网页来源都要求精确消息
- `apps/extension/src/platform/extension/router.test.ts`：新增顶层页面发送非 cosmetic 消息被拒绝的断言
- `SECURITY.md`：更新消息路由安全边界描述

**验证：**
- 单元测试：`router.test.ts` 覆盖顶层页面发送 `getBlockingStatus`、`pauseBlockingForSite`、`refreshBlockingSubscriptions` 均被拒绝
- E2E 测试：现有 `bilibili-adblock.spec.ts` 继续通过（cosmetic rules 正常工作）
- 安全边界：网页内容脚本无法触发站点暂停或规则刷新

**后续：** 无；该策略现已与注释和 `SECURITY.md` 一致。
