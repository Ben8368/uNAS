# 治理经验

- G-001：未跑客观验证不得标记“已验证”；没有真实浏览器或用户体验证据时，不得把主观项写成完成。
- G-002：入口只保留路由和硬边界；长计划、命令手册、历史和复盘下沉到专题文档或 `docs/archive/`。
- G-003：风险是尚未验证的外部不确定性；技术债是实现后有意保留的妥协，二者不能互相代替。
- G-004：用户限定写入范围时只改指定范围；需要同步其他事实源时，先作为未执行项说明。
- G-005：共享会话、库文档和现有项目只能提供背景，不能自动变成 uNAS 的已接受决策或已验证能力。
- G-006：探针详细证据在 `benchmarks/<probe>/README.md`，Context 只保留链接化摘要；更新任一验收结论时反向核对 Context、probe 与风险台账，冲突以探针环境/步骤记录为准并同次修正。
