# ADR-0010：自有 MMKV 兼容实现采用 clean-room 路线

- 状态：已接受
- 日期：2026-09-20

## 背景

`unlock-music.dev/mmkv@v0.1.0` 的公开镜像可以固定来源 tag，但 tag 树没有 `LICENSE`、`COPYING` 或 `NOTICE`，也没有可复核的 MIT/BSD 许可声明。它只能作为功能和格式研究线索，不能作为可再分发源码依赖。当前 uNAS 源码中没有对该模块的实际引用；SP-09 中的记录是审计证据，不是产品依赖。

## 决策

1. uNAS 不复制、改名、改许可证或继续依赖 `unlock-music.dev/mmkv` 的源码；上游 `go-mmkv` 只保留为不可分发的审计参考。
2. 如后续确需 MMKV 能力，必须在 uNAS 仓库内独立实现兼容所需的最小行为。允许参考公开的格式事实、接口行为和测试现象，但不复制上游源文件、代码片段、注释、测试资源或构建物，也不把上游实现直接移植进来。
3. 自有实现进入仓库前，由维护者为该实现选择并提交 uNAS 自有许可证文件；该许可证只覆盖 uNAS 自有实现，不追溯覆盖上游代码。未完成许可证选择、来源记录和独立实现审查前，不进行公开分发或产品集成。
4. 独立实现必须保留 clean-room 证据：需求/格式事实、独立代码来源、由 uNAS 自行编写的测试、输入与预期结果哈希，以及与上游源码的隔离记录。

## 后果

- 上游 `go-mmkv` 的许可证阻断不再阻断“自有实现”路线，但若要复用 `um/cli` 的原始 Go 依赖，阻断仍然存在。
- 本 ADR 不授权读取、收集或分发用户本机 MMKV/KGG 数据库，也不改变浏览器扩展的本地授权、密钥和文件边界。
- 在独立实现完成并通过单独审查前，QMC 的 MMKV/文件路径分支和 KGM v5 仍保持未验证/不支持。

## 替代方案

- **继续依赖上游 `go-mmkv`：** 因缺少许可证/再分发授权而拒绝。
- **为上游代码补发 MIT/BSD：** 无权代表上游作者作出该授权，拒绝。
- **直接把 Go 实现移植到 TypeScript：** 仍可能复制受保护的代码表达，不满足独立实现证据要求，拒绝。
