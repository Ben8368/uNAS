# ADR 0023：项目级 WebDAV 共享连接

- 状态：已接受
- 日期：2026-10-10
- 背景：维护者明确要求整个项目复用 WebDAV，配置后自动完成密码库设置，取消各 App 重复填写认证信息。
- 替代范围：替代 ADR 0014/0015 中“不得复用连接材料”、Files 不持久化配置和独立连接表单的条款；不改变 Vault Key 隔离、文件预算、上传同意和条件写入限制。

## 决策

- 项目连接归 `platform/webdav`；地址、名称、修订号与认证信息是单一事实源。普通 projection 仅含连接元数据；认证信息由后台设备密钥 AES-GCM 加密保存，设备密钥复用既有 IndexedDB 存储标识以兼容旧数据。Vault 只保存连接 ID 和自己的加密密钥，不将 Vault Key 放入共享连接。
- 统一设置表单在 Settings；Files 选择共享连接，密码管家、旧 manage 页与密码浮窗指向同一设置入口。新 App 经共享 port/adapter 接入，不能将凭据放入 React/桌面状态或从 UI 导入网络传输。
- 旧独立 WebDAV 配置消息保留来源校验后明确拒绝并指向统一设置，不再创建分叉配置；既有 Vault 的读取、锁定和本地迁移继续保留。
- 保存前须明确同意本机保存、项目复用和加密密码库同步；手势中申请单一 HTTPS origin。后台再次检查权限和字段，再用 Depth:0 验证服务器根目录，失败不替换已有配置。普通文件仍仅在用户选择上传时发送。
- 保存连接后自动创建/接入根目录下 `.unas-vault/` 的加密密码库；恢复密钥放在高级选项，新库创建后必须显示备份密钥。远端已有库且没有密钥时失败，不能覆盖。连接保存与 Vault 初始化是分开的结果：后者失败仍保留可用文件连接，显示原因并允许重试，不假报全部成功。
- 旧 Vault 配置首次读取共享连接时做仅本地、可重入迁移，保持原端点和密钥；长期材料改存连接 ID，显式锁定的会话不得被迁移重新解锁。旧本地解锁信封可保留历史加密材料，但使用时按 profile 绑定读取当前共享认证，下一次设置/解锁重写为引用。
- 配置操作在后台串行化。端点不原地换服务器，需添加新连接；更新生成新修订号。Files 在每次操作及 Range 分段前核对修订号和权限；更新/删除后旧会话拒绝继续操作，已发出的远端请求不保证撤回。页面关闭释放文件会话，持久配置保留。
- Files 隐藏并禁止访问 `.unas-vault`；迁移的原根目录额外保护 `objects`，防止普通文件操作破坏密码库。文件操作、范围读取、容量预算和错误归一仍归 Files adapter。
- 版本化 `webdav.connection` 路由只接受同一扩展的顶层 New Tab/Workspace；拒绝网页、子 frame、其他扩展和浮窗。内部 acquire 返回认证信息给受信任 Files adapter，不返回 Vault Key；浮窗只能经既有 capability 校验请求打开设置。
- 移除连接同时解除关联密码库的本地配置；不删除远端文件或加密对象。无文件自动上传、新增必需权限、远程代码或新依赖。

## 后果与替代方案

配置一次即可供项目内已接入的 App 使用；未来 App 仍须声明自己的网络操作、预算和用户意图，不能借共享认证自动上传数据。设备加密沿用本机信任边界，不宣称抵御已控制浏览器 Profile 的攻击者。拒绝把 Vault Key 当项目通用凭据、复制各 App 密码配置、或在密码库初始化失败时报告全部成功。

真实 NAS、原生主机授权/撤销、跨页在途请求及用户 Profile 验收继续登记在 [RISK-016](../RISK_REGISTER.md#risk-016p1共享-webdav-传输的真实服务兼容性待验收)。合成测试不代表 NAS 通用兼容。
