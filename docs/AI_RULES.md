# AI 开发与审查规则

> 协作入口见 [AGENTS.md](../AGENTS.md)，当前状态见 [CONTEXT.md](../CONTEXT.md)，文档治理见 [GOVERNANCE.md](GOVERNANCE.md)。

## 1. 工作顺序

```text
读取 Context / Lessons → 确认当前阶段与事实源 → 修改 → 红绿灯审查 → 客观验证 → 更新唯一权威文档 → 汇报
```

- 答疑或评审只做只读检查，除非用户同时要求修改。
- 诊断先确定原因并给证据；用户没有要求修复时，不顺手扩展实现。
- 构建任务要完成安全范围内的实现和验证，不以“给出方案”代替落地。
- 默认不自动提交、推送、发布、上传或创建外部资源。

## 2. 红绿灯审查

产品源码发生变化后、运行完整验证前，必须输出：

```markdown
## 🚦 Audit Report

**总体评价：** [ 🔴 阻断 / 🟡 可通行 / 🟢 通过 ]

**1. 🔴 阻断项：**
- 无 / 具体问题

**2. 🟡 跟进项：**
- 无 / 具体问题及权威登记位置

**3. 验证计划：**
- 命令、真实路径与未覆盖项
```

审查至少覆盖：

- **真实性**：文件、API、格式、codec、浏览器和性能结论是否有证据。
- **范围**：是否符合 Product、Roadmap 和本轮用户授权。
- **分层**：UI 是否绕过 contract / task / adapter 直接碰引擎或特权 API。
- **资源安全**：是否有大小预算、并行度、取消、超时、Worker/句柄/临时文件清理。
- **异常路径**：错误、空态、权限拒绝、能力缺失和降级是否可读且不假成功。
- **兼容性**：是否经过 feature detection，而不是只相信类型或库文档。
- **供应链**：依赖、WASM、素材、字体的来源、版本、许可、哈希和包体影响。
- **可测试性**：规划/路由/状态机是否可独立测试，真实浏览器路径是否有验收证据。

分级：

- 🔴：安全越界、架构逆依赖、假成功、数据丢失、契约破坏、无授权分发或当前阶段越权。
- 🟡：不阻断当前目标，但存在已登记的兼容性、性能、可维护性或主观验收缺口。
- 🟢：范围内目标完成，客观验证通过，没有未登记风险。

🔴 不得合并或宣称完成；🟡 必须进入 `RISK_REGISTER` 或 `TECH_DEBT` 的唯一匹配位置。

## 3. 验证层级

| 变化 | 最低验证 |
| --- | --- |
| 仅治理文档 | `node scripts/governance-docs-check.mjs` |
| 纯类型 / contract | 文档检查 + typecheck + contract tests |
| 引擎 adapter / Worker | 上述 + 固定夹具 + 取消/错误/资源清理测试 |
| Frontend Demo / UI | 上述 + mock scenario + 组件/视觉测试 + 目标扩展 E2E + 响应式/错误态人工确认 |
| Extension | 上述 + Chrome 解包扩展真机 + 权限/CSP/WASM 验收 |
| 性能或大文件承诺 | 固定设备/浏览器/夹具基准，记录峰值内存、耗时、输出正确性和失败模式 |

未执行的项写“未运行”及原因；不得把 CI 绿灯替代主观体验或真实浏览器能力验证。

## 4. 实现约束

- 禁止占位成功、静默忽略字段、无期限 TODO、组件内硬编码能力矩阵。
- Frontend Demo 的 mock 必须显式标记且不生成假文件；真实 adapter 接入前不得升级格式支持状态。
- New Tab 不预加载 engine/WASM，不成为长任务唯一 owner；Workspace/Service Worker 生命周期按架构边界实现。
- Link App 只处理声明式 HTTPS URL，不加载远程模块、iframe App 或用户代码。
- 公共类型进入 `packages/contracts`；状态机与路由进入 `packages/core`；引擎细节留在 adapter 包；Worker entry 不承载 UI 语义。
- 任何任务都必须有稳定 ID、明确终态、可取消信号、错误分类和资源清理策略。
- 能力探测结果必须包含“为何不可用”和安全降级，不用单一布尔值掩盖部分能力。
- 跨 Worker 传输优先使用 Transferable / Stream / handle；避免无审计地复制大型 `ArrayBuffer`。
- 单文件超过 350 行时说明职责；超过 450 行先评估拆分；超过 500 行默认至少 🟡。

## 5. 文档与 Git

- 只更新发生事实变化的权威文档，遵守 [GOVERNANCE.md](GOVERNANCE.md)。
- 提交信息使用 Conventional Commit 类型；一次提交只表达一个可审查主题。
- 不修改或清理用户的无关改动，不使用破坏性 Git 命令。
- 用户明确要求提交时，提交前列出验证结果；保护分支和任何 push 仍需符合用户明确范围。
